## 2.1 Expanded B1 scan after Sonnet challenge — updates, human reply, fast ACK and ledger completeness

Native `Webhooks::Trigger` handles failures for BOTH `message_created` and `message_updated`, so leaving all updated callbacks on 422 risks the same pending→open/SAME_AGENTBOT failure.

**B1 event classes to evaluate together (not seven serial mini-campaigns):** own public bot outgoing, narrow native EmailCollect/greeting/OOO/CSAT templates, private note (including §44 delayed handoff mentions), public HUMAN_USER outgoing, and `message_updated` for each of outgoing/template/private/incoming. Native private notes are INTERNAL to `filter_internal_messages=true` and normally do not require a public ledger entry, whereas public bot/template/human rows do.

**Fast ACK without synchronous Chatwoot REST is a PROPOSED ALTERNATIVE, not an authority proof:** HMAC authenticates provenance of the signed Chatwoot trigger, *not* arbitrary current source truth, sender category, message mutation or correct episode ownership. Variant F (provisional) returns `2xx` only for a strictly bounded signed, fully-shaped, target-scoped **provably noncustomer** transport event, with no immediate public send or customer decision; no authoritative source inference is allowed from the payload. The contract still requires a reliable path to reconcile **every public** row (bot/template/human) into the existing event ledger before any S2 public authorization. Current CP1 has no independently proved eventual-writer/reconciliation guarantee for `2xx`-ACKed but unrecorded rows. If it does not, F may reduce Chatwoot failures while causing S2 permanent fail-closed and must be REJECTED for this complete B1 fix. No added durable queue/proxy is allowed by default.

**Conservative variant R (existing API read):** use the current official scoped Chatwoot exact-message reader and v4 event ingestion/identity protocol; distinguish `INTERNAL` private from public `SYSTEM_TEMPLATE`, `BABYPARK_PUBLIC_REPLY` and `HUMAN_PUBLIC_REPLY` with required semantic ownership/reconciliation and idempotency before successful acknowledgment. The current API reader returns `INTERNAL` without sender/full event, so proving an authoritative private category may require a reviewed native projection, not guessing. Variant R is a **fit candidate subject to correctness/performance proof**, not automatic approval.

**S2 backstop proof (existing exact code, not hypothetical):** `src/copilot/chatwoot-client.mjs#readAuthorizingConversationSnapshot` returns a full filtered Chatwoot PUBLIC snapshot; `src/copilot/first-line-s2-preflight.mjs` compares its row count and every source event to `store.listConversationEvents`, returning `S2_HISTORY_TOPOLOGY_CHANGED` / `S2_HISTORY_TOPOLOGY_UNPROVABLE` on mismatch, before facts/owner/public send; `tests/unit/first-line-s2-covered-text.test.mjs` already checks an additional public row fails. A template with unknown sender/content type remains UNKNOWN/fail-closed rather than silently accepted. **Scan disposition for the expanded subproblem:** no new native AgentBot per-type subscription appeared in the pinned source; the Chatwoot account-wide keep-pending flag still hides genuine failures, not a safe solution.
