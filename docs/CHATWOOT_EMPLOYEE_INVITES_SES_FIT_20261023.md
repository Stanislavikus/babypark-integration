## Exact integration/data/security scope

BabyPark retains customer-message/transcript authority solely in Chatwoot; **no customer emails** are allowed to be sent in this stage. No S3, SNS, inbound MIME storage or receipt rules. Employee-account email address and confirmation link (time-limited credential) are transmitted from Chatwoot through AWS SES to Zoho Mail, with AWS handling mail transport and standard bounce/complaint metadata. The existing employee account rows and confirmation tokens are in Chatwoot DB. No new routine BabyPark storage or raw message copies. Official Chatwoot and Zoho already process those personnel records; AWS as a new processor requires acceptance of official AWS data-processing/service terms and applicable personnel privacy review before external sending. SES can process mail-related metadata/traffic outside chosen region for delivery; do not assert EU-only end-to-end storage.

Blast-radius: enabling Chatwoot's one global SMTP transport may also send queued or future system/event emails. Sandbox restrictions limit *unverified* external recipients, but allow any verified @babypark.ua recipient, and future AWS approval could remove this fence. Therefore this stage is time-bounded pilot to get staff confirmed; no assumption global SMTP is an indefinite employee-only configuration, and subsequent SES production approval triggers recheck before any customer send. Never enable Website continuity or notifications to outside verified scope until separately gated.

Secrets: existing owner-held SES regional SMTP username/password (not the IAM access secret) must be entered directly into the mode0600 Chatwoot .env from user's secure DigitalOcean terminal. No copy to chat, GitHub, remote terminal tool output, bash history, PR, backup output or logs. Operator may add nonsecret approved env lines only after owner GO. Work only on already installed native configuration; no custom scripts/Chatwoot code/SDK. Do not echo passwords, even as diagnostic. IAM SMTP credentials have only SendRawEmail From=contact@ or support@; sender `MAILER_SENDER_EMAIL` MUST be one of those addresses. Default is forbidden. Prefer `support@babypark.ua` only after verified mailbox/replies; if not deliverable, owner must separately approve `contact@babypark.ua` (currently receiving group alias) as system From.

Operational setup at authorized activation: protect rollback as root-only snapshot of **config metadata/bytes**, never expose secret; set SMTP_ADDRESS=email-smtp.eu-central-1.amazonaws.com, SMTP_PORT=2587, SMTP_AUTHENTICATION=login, SMTP_ENABLE_STARTTLS_AUTO=true, SMTP_SSL=false, MAILER_SENDER_EMAIL=BabyPark <support@babypark.ua> (or owner-approved contact@ alias); verify SMTP_DOMAIN babypark.ua; read SMTP_USERNAME/SMTP_PASSWORD from owner-only hidden input; preserve 0600 chatwoot ownership. Reload both web and worker via documented systemd unit restart only after scope/backup and approval. Rollback reverts exact previous .env atomically, restores permissions and service, checks live endpoint + workers and mailer sending state. No authorization to implement until owners confirm.
