## Decision

**NO-GO for production installation, and NO-GO for real customer data.** The exact 2.49.8 filesystem-persistence, missing-mount startup guard, independent full restore/key-decryption, and same-limit SQLite/PostgreSQL comparison were not verified. The production host's worst observed MemAvailable is only about 1.24 GiB, while the successful fresh 2.49.8 database migration needed a 1,200 MiB no-swap container limit. That leaves about 69 MiB at the measured low-water mark before Docker overhead or an OS/Chatwoot reserve. Low message volume does not close this peak-resource gap.

No Docker, n8n, storage path, service unit, or backup was installed or written on production. Chatwoot, Viber, customer messages, and real credentials were not touched. The successful 22-node and 6-node native workflow imports were **not repeated**.

## Independent blocker classes and closure evidence

1. **Runtime data-path enforcement.** Trace: only v2.43.7 has prior sentinel evidence; the current DEV tmpfs exists, but its old service is not bound to an active systemd mount dependency. Violated invariant: no customer payload may reach durable storage and missing `noswap` must fail closed. Minimal stock correction: exact 2.49.8 variables + host tmpfs bind + explicit mount unit requirement. Regression evidence: valid native synthetic normal/error/manual/wait executions; scan SQLite/WAL/SHM, tmpfs, eventBus and Docker logs; negative/positive service-start checks.
2. **Recovery and encryption continuity.** Trace: no full clean-instance restore or dummy credential decryption result. Violated invariant: portable backups must recover DB, key and credentials as a coherent set. Minimal stock correction: consistent full user-folder/DB snapshot and protected key backup. Regression evidence: restore on clean isolated instance, `PRAGMA integrity_check`, same-version startup, dummy credential decryption without printing the value.
3. **Shared-host peak capacity.** Trace: 1,200 MiB migration cap vs. 1,269 MiB worst observed MemAvailable. Violated invariant: n8n must not degrade Chatwoot/Viber and must retain an OS/service reserve with swap disabled. Minimal correction: resize the chosen shared host and bound n8n cgroups; do not move production n8n to a separate VM. Regression evidence: production read-only baseline plus bounded install/migration and synthetic concurrency run with reserve and Chatwoot latency distribution recorded.
4. **Database/concurrency choice.** Trace: no equal-limit SQLite/PostgreSQL comparison. Violated invariant: select a stock design based on measured behavior and recoverability, not assumption. Minimal correction: compare only official supported layouts with the same resource limits and workflow load. Regression evidence: migration/steady-state peak, two-workflow concurrency, integrity and restore results for both.
5. **Release governance and storage inventory.** Trace: incomplete fit note, no exact SHA-bound owner pre-code authorization, and no n8n storage records. Violated invariant: no implementation/config stage before frozen fit and §3 approval; no write before storage declaration. Minimal correction: complete/freeze fit; owner `integrate` for exact digest; then one bounded implementation PR registers every class before first write. Regression evidence: exact base/HEAD/tree, Agreement-required review, config tests if `config/**` changes, independent zero-blocker review, no merge without separate owner GO.
