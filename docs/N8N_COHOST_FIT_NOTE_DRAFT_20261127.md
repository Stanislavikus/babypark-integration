## Bounded function and ownership

Release 2 will install **only** official n8n with native Docker Compose, a separately owned data directory/DB and independent runtime lifecycle. The editor/UI and public webhook paths must not be reachable from the internet. Two verified DEV workflow definitions may be imported **inactive** into a fresh database; no old DEV SQLite volume, execution logs, existing plaintext/old encrypted credentials, Anthropic key, Chatwoot API access token, customer data or live webhook registration may be imported. The legacy DEV n8n remains unchanged and inactive for recovery comparison.

The owner explicitly selects **co-location** for low current volume (~5 customer chats/day), with a later joint Chatwoot+n8n+Odoo move to Hetzner and capacity-based host scaling. Deployment as a separate production n8n VM would violate the owner's placement decision. Odoo remains out of scope until its own install/change campaign. Chatwoot Web/Worker, existing Postgres and Viber Gateway must not be changed, restarted, or share the new n8n database.

Recommended official vendor runtime (from DEV pull and CLI inspection): `docker.n8n.io/n8nio/n8n@sha256:9a83f64039070a846723cdf7d95b85db9ad1e6fadb38cad1ca12eceb04e04f33`, n8n **2.49.8** (stable release 2026-11-27). No `latest`, no auto-update. An official SQLite-in-one-container layout is the lowest steady-state overhead for the two inactive workflow definitions and lowest onboarding complexity on the 4-GiB host. A separate official PostgreSQL Compose variant is the fallback for demonstrated SQLite fit failure, concurrency or backup requirements, not a mandate to share Chatwoot PostgreSQL.

## Restart, concurrency, backup, rollback

- Independent `/opt/babypark-n8n/` declarative Compose project, root-only local secrets, loopback-only `127.0.0.1:5678` or a separately approved private HTTPS operator route, n8n UI not publicly accessible. No changes to Viber/Nginx WebSocket routes.
- Explicit new persistent classes must be registered in canonical `config/storage-policy.yaml` **before their first write**: n8n SQLite/sidecars, n8n user folder/keys, runtime meta, backups, tmpfs scratch/execution/event logs, Compose settings and any Docker-managed named volume/source; update `docs/INFRASTRUCTURE_REGISTRY.md` and `docs/CURRENT_STATE.md` with actual post-install identities.
- Use official n8n backup/export and a consistent DB snapshot plus the **same encryption key** stored in restricted encrypted backup; a ZIP of workflow JSON alone is not recoverable credentials. Backup restore must be tried on a clean isolated host with official same version before declaring portability PASS. No secret values in Git, console or reports.
- Pin n8n container digest; after future n8n schema migrations rollback must restore matching pre-update DB/config/key, never merely switch image to old version. A Chatwoot vendor upgrade must not automatically change n8n config/code/volumes or start/stop the n8n unit.
- Every workflow remains inactive throughout Release 2. There is no shared webhook owner, no customer message send/deduplication change, and no production token to allow live POST. When storage unknown, encryption key absent, or noswap mount missing: do not start the service.
- Planned install recovery: stop only newly installed n8n Compose project, preserve its immutable preimage and verified backups, confirm Chatwoot and Viber original health, record rollback. Do NOT remove any existing Docker volumes or external n8n DEV installation.

## Quality, complexity and integration decision

One official stock n8n deployment reuses the owner-tested 22+6 native graph without custom connector code and without rebuilding native workflows in Node-RED or Activepieces. It has lower migration/regression burden than rewriting. The alternative scan names all considered candidates and licenses. Runtime application work is bounded to official installation and host configuration only; **production custom code: NONE**. Official use remains free at the defined internal-use boundary, subject to owner acceptance. Operational cost is the shared host's RAM/CPU/disk and protected backup storage; no additional VM/cloud subscription is authorized. Current recommendation: **`PoC-only`** for synthetic tests on an already available eligible rehearsal environment. There is no `integrate` recommendation until target-version storage, actual memory peak, restore/key-decryption and service-guard evidence pass and the owner authorizes the exact frozen fit digest.
