### Deferred release requirements — explicit STOP

This is **not** consent to configure a live Chatwoot SNS subscription, create DNS MX, enable/activate SES rule, distribute AWS credentials, change Rails `.env`, restart web/Sidekiq, alter Zoho SMTP, or send real email. Those operations cross customer-data, durable storage, sender-identity and public endpoint boundaries and need a new merged-Agreement-compliant HEAVY manifest/review, exact owner approval and rollback. Standard official SNS DLQ is attached to a **subscription** at activation time, not SNS topic now. Rails responds HTTP 204 before background processing, so SQS DLQ only protects failures *before* successful receipt; separately test ActionMailbox raw MIME storage, Sidekiq retries/dead queue, Message-ID dedup, malformed/spoofed UUID and sender under an isolated Chatwoot instance. Do not use an active Website Inbox or make a real customer contact for tests. Failed SQS notification may reference an S3 object removed by the 14-day lifecycle; align retention and operator alert / replay SLA before activating. Observability and manual-native replay SOP are required; no custom worker.
