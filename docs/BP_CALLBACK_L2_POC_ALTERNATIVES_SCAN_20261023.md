## Independent blocker beyond Sonnet: browser behavior cannot constrain public API request shapes

Even if the intended frontend sends an anonymous contact with **no** phone/email/identifier and keeps a synthetic phone in `Conversation.custom_attributes`, a hostile HTTP client can independently call the same API-inbox `contacts#create` with `phone_number` and receive matched existing-account contact profile PII. This is a **path-level** risk independent of our launcher form. Frontend field omission, CORS, Origin/Referer checks and IP throttles **do not** enforce invariant. `hmac_mandatory` off by default. Turning it on requires a trusted server to mint/verify identifier hashes with a secret, or an independently proven stock intermediary. Cloudflare WAF request-body inspection fields `http.request.body.raw`, `.form` and `.size` require Enterprise (official 2026 reference), so cannot assume a free WAF request-field allowlist. Turnstile client-side without server Siteverify also does not fix this. No proven native free configuration-only guard exists in this scan. Any separate server edge gateway/validated access is a NEW bounded architecture decision, not authorized by this scan.
