## 2. Data/connectivity and unchanged frozen invariants

Webhook received from Chatwoot **AgentBot** via signed raw payload `X-Chatwoot-Signature`, timestamp and delivery ID. Strict configured account/inbox/agent-bot provenance; signed body is a **locator only**. For actions requiring authority, re-read the *exact* current Chatwoot source message over official, scoped, authenticated Chatwoot REST before classifying semantic type. Never equate a mere signed claim to proof of customer or proof of benign event when it could hide ambiguity or contrary state. Chatwoot owns the transcript; BabyPark persists only allowed v4 semantic metadata, never raw/normalized customer bodies/emails/phones/attachment URLs/content hashes. No sender identity, event shape, source row, origin, revision or Human ownership guessed. No public POST, customer-turn/action write or speculative source mutation for safely classified noncustomer events. **Public** bot/template/human rows are nevertheless part of the existing v4 Chatwoot topology and may require a bounded noncustomer metadata ledger entry; private INTERNAL rows are excluded from public history. The current S2 whole-history equality rule forbids treating an unrecorded public event as if it did not exist. Existing durable v4 writer/transaction/lease/CAS and rollback rules remain untouched.

Customer-facing dynamic facts (price, stock, policy, hours) require live authority immediately before action; nothing in this ACK hardening authorizes a public reply or new semantic decision. `pending→open` with SAME_AGENTBOT and no human assignee is NOT HUMAN. Durable HUMAN and operator-attention under frozen `AI_FIRST_LINE_DESIGN.md` §29.8.2 remain separate mandatory requirements and are not waived by this B1 fix. Bot webhook acknowledgment and end-user visible/human receipt are different acceptance layers.

**No production connectivity or activation** in this stage. **BLOCKING pre-code design questions and required proof:**
A) `message_updated` is a source-proven AgentBot event path (Chatwoot v4.18 `Message.after_update_commit` → `dispatch_update_event` → `AgentBotListener#message_updated` for incoming/outgoing/template, even private). Freeze separate cases for noncustomer/public, noncustomer/private, and edited incoming Contact. Exact channel frequency/change attributes were NOT runtime-measured.
B) **Fast ACK candidate vs truth:** a valid signed Chatwoot envelope can justify treating an event as a transport trigger but does NOT become exact current row, correct sender or durable source identity. Evaluate a tightly bounded, verified-scope, fully specified no-REST `2xx` for a provably noncustomer class as an experiment ONLY; prove no unsafe admission, no dropped public event, replay/idempotency, and successful bounded topology reconciliation. Without that proof, reject this path, not silently adopt it.
C) **Public ledger completeness:** `chatwoot-client.mjs#readAuthorizingConversationSnapshot` includes public bot/template/human rows; `first-line-s2-preflight.mjs` compares every row to `store.listConversationEvents` before any send. A fast `2xx` with zero public topology ledger write must either have an independently proven bounded existing-store reconciliation path BEFORE S2 or will leave S2 `STALE/HUMAN_REQUIRED` indefinitely. Frozen §29.5–29.7.2 outranks a convenience fast-ACK rule. `tests/unit/first-line-s2-covered-text.test.mjs` already proves extra public rows fail S2.
D) **Private note/§44:** the current exact Chatwoot reader emits `INTERNAL` without a full sender proof; discover whether stock API or authenticated native envelope supports a safe positive private ACK under the frozen contract. If not, HALT this subcase, rather than letting the alert note itself silently cause B1.
E) **Human reply (E3):** public `HUMAN_PUBLIC_REPLY` must fence further AI under §43 and remain in v4 continuity. A `200 ignored` without durable HUMAN/ownership handling is not acceptable even if S2 would temporarily block on missing topology.
F) **Read performance:** stock `WEBHOOK_TIMEOUT=5s` for Chatwoot. Exact REST + ledger store may exceed it; measure bounded latency in synthetic integration and test unavailable/slow API. The 5s timeout cannot be magically bypassed by a `2xx` without reconciling the public rows. `503` semantically fail-closed but does not complete native HUMAN transfer.
G) No ACK alone proves HUMAN or durable operator attention; §29.8.2 remains a separate hard requirement; sender/account/inbox/row unknown always denies.

**S2 confirmation:** `src/copilot/first-line-s2-preflight.mjs` lines 103–169 require full PUBLIC history, exact covered customer text and fresh `pending+SAME_AGENTBOT` current ownership before even the non-authorizing preflight. `tests/unit/first-line-s2-covered-text.test.mjs` validates rejection of an extra public row and ambiguous reclassification. This is a **safety backstop**, not evidence that an unpersisted public row can be ignored while preserving dialogue liveness.

Do not assert all known-ignored events can be safely ACKed until A–D are resolved in testable code/review. If this matrix is internally contradictory with frozen C6 semantics, **HALT** and obtain owner decision rather than stealthily broadening ACCEPT.
