## 2. Static candidate model and time-budget guard (no code selected)

For a candidate DELETE one-transaction success path with no preliminary read-tx, `PRAGMA cache_spill=OFF` verified and no extra SQL acquisition sites: **one BEGIN IMMEDIATE site + one potentially reader-blocked DELETE COMMIT site = structural `K_single_success=2`**. This is NOT an upper bound for error/rollback, other same-loop admitted callbacks, reader/backup contention, triggers, or any unknown SQLite internal sites. With WAL, the usual DELETE-style COMMIT-reader wait is absent, but **do not set `K_WAL=1` by fiat**: writers still serialize, checkpoints/last-connection cleanup/recovery may stall or surface `SQLITE_BUSY`, and auto-checkpoint work can delay COMMIT. Actual `K_total` comes from the single-connection process/cumulative-admission proof and measured/engine-bounded exception sites, not a guessed constant. `K_total ≤ 2·A_max + K_extra` applies **only** to successful DELETE transactions after all conditions are proven; error paths get separate site accounting. WAL requires a new site model.

**Remaining-budget guard before the ONLY `BEGIN IMMEDIATE`:** capture authoritative monotonic request-admission time `t0` and fixed candidate safe deadline `T_safe=T_webhook−M`; after exact REST read and *immediately before* synchronous BEGIN compute `remaining = T_safe − elapsed_since_t0`. If `remaining` cannot cover the **independently evidenced conservative upper envelope** for the remaining `B_site(begin)` + overshoot, synchronous semantic/store time, potential `COMMIT`/checkpoint/abort sites, response completion and competing work, **deny before opening a transaction**. A nonpositive remaining budget also denies. A sampled percentile or a synthetic `E=...` branch-test value is NOT a production worst-case envelope and cannot authorize acceptance. The time guard is **defensive admission**, not an interrupt: synchronous `node:sqlite DatabaseSync` can block the entire Node event loop including body/REST timers and watchdogs. Bound native per-connection `busy_timeout` and fail-closed busy results separately; verify effective read-back, and reject `await`/thenables inside `tx()`. Do not use an assumed 5000ms store default (current code uses 5000) as a safe callback budget. After BEGIN no JS timer can guarantee preemption. If no defensible envelope is demonstrable, **HALT**, not an arbitrary `M` or status code.

**Single-connection rule:** only the owner ingress process creates/opens exactly one live owning writable `DatabaseSync` to episode.sqlite at runtime; no hidden second copy in the same OS process/event loop from startup checks, migration, backup, module imports or rolling overlap. Startup must attest connection count, schema, PRAGMA busy_timeout/cache_spill/journal_mode/synchronous and reject unexpected connection/invalid read-back. Separate recovery/B2 connections are external competitors requiring separate bounded lock/I/O proofs. A rejected/slow-body request should not open additional connections. This topology is **proposed for later code**, not implemented/attested today: [current store constructors](https://github.com/Stanislavikus/babypark-integration/blob/565d8de08fbd8e85598e554cb91e59dfa4f8c1a4/src/copilot/first-line-state-store.mjs#L2472-L3083), [ingress open](https://github.com/Stanislavikus/babypark-integration/blob/565d8de08fbd8e85598e554cb91e59dfa4f8c1a4/src/copilot/first-line-runtime-ingress.mjs#L54-L69).
